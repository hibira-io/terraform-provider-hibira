# Hibira Provider

[Hibira](https://hibira.io) is a hosted, Pusher-compatible realtime WebSocket service. This provider manages its apps, their webhooks and their push notification (Beams-compatible) credentials, so each environment's realtime setup lives in Git with the rest of your infrastructure, and app keys and secrets flow straight into the other resources that need them.

## Authentication

In the Hibira portal, open [AI agents](https://hibira.io/portal/agents) and create a personal access token with **read and write** access (a read-only token can only use the data sources). Set it as `HIBIRA_API_TOKEN`, or pass it to `api_token` from a variable; don't commit it.

A token limited to one app can manage that app's webhooks and push settings, but can't create apps.

## Example Usage

```terraform
terraform {
  required_providers {
    hibira = {
      source  = "hibira-io/hibira"
      version = "~> 0.1"
    }
  }
}

# Make a token with read and write access in the Hibira portal, then
# export HIBIRA_API_TOKEN=hkb_pat_... (or set api_token).
provider "hibira" {}
```

```terraform
resource "hibira_app" "chat" {
  name            = "chat-prod"
  client_events   = true
  allowed_origins = ["https://example.com"]
}

resource "hibira_webhook" "presence" {
  app_id = hibira_app.chat.id
  url    = "https://example.com/hooks/hibira"
  events = ["member_added", "member_removed"]
}
```

## Schema

### Optional

- `api_token` (String, Sensitive) A Hibira API token (`hkb_pat_...`) with read and write access, made on the Hibira portal's AI agents page. Can also be set with the `HIBIRA_API_TOKEN` environment variable.
- `endpoint` (String) The Hibira site URL. Defaults to `https://hibira.io`, or the `HIBIRA_ENDPOINT` environment variable.
